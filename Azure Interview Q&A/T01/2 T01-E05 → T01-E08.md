# 1. 🔴 M IMP — Azure Fundamentals, Architecture & Resource Hierarchy

## Easy

### **T01-E05. What is an Azure region?**

**Answer:**
An Azure region is a **geographical area that contains one or more Azure datacenters and the networking infrastructure connecting them**. When I deploy most Azure resources, I select a region such as Central India, East US, or West Europe.

The region matters because it affects:

* **Latency** — resources closer to users usually provide lower latency.
* **Service availability** — not every Azure service or SKU is available in every region.
* **Compliance and data residency** — organizations may be required to keep data within a particular geography.
* **Cost** — pricing can differ between regions.
* **Resiliency** — some regions support Availability Zones and other resiliency capabilities. ([Microsoft Learn][1])

**Example:**
If most of my application's users are in India, I might choose an Indian Azure region to reduce latency and satisfy data-residency requirements. Before choosing it, I would also verify that services such as AKS, the required VM sizes, and Availability Zones are supported there.

**Memory line:**
**Region = geographic location where Azure resources run.**

**Interview trap:**
An Azure region is **not necessarily a single datacenter**. A region contains a set of physical facilities, and many regions also contain multiple Availability Zones. ([Microsoft Learn][1])

**Keywords:** Azure region, geography, latency, data residency, service availability, resiliency

### **T01-E06. What is an Azure Availability Zone?**

**Answer:**
An Azure Availability Zone is a **physically separate group of one or more datacenters inside an Azure region**, with independent power, cooling, and networking.

The purpose is to protect a workload from a **datacenter or zone-level failure**. If I distribute application instances across multiple zones, the application can continue operating even if one zone becomes unavailable. ([Microsoft Learn][2])

There are two important deployment models:

* **Zonal resource** — deployed into one specific Availability Zone.
* **Zone-redundant resource** — distributed or replicated across multiple zones, with Azure managing the redundancy for supported services. ([Microsoft Learn][2])

**Example:**
For a production web application, I might run VM or AKS capacity across Zones 1, 2, and 3 and use a zone-redundant database or load-balancing service. If Zone 1 fails, workloads in the other zones can continue serving traffic.

**Memory line:**
**Region protects location choice; Availability Zones provide isolation inside the region.**

**Interview trap:**
Availability Zones protect against **zone-level failures, not a complete Azure region failure**. For region-level disaster recovery, I need a multi-region strategy. ([Microsoft Learn][2])

**Keywords:** Availability Zone, independent power, cooling, networking, zonal, zone-redundant, high availability

### **T01-E07. What is an Azure subscription?**

**Answer:**
An Azure subscription is a **logical management and billing boundary for Azure resources**.

Resources are deployed inside a subscription, and the subscription provides important boundaries for things such as:

* billing and cost tracking,
* Azure RBAC,
* Azure Policy and governance,
* service quotas and limits,
* resource organization.

An organization can have multiple subscriptions under the same Microsoft Entra tenant.

**Example:**
A company might use separate subscriptions such as:

* `Production`
* `Non-Production`
* `Shared-Platform`

This gives stronger separation of permissions, policies, costs, and blast radius than putting everything into one subscription.

**Memory line:**
**Subscription = resource-management + billing boundary.**

**Interview trap:**
A subscription and an Entra tenant are **not the same thing**.

The **tenant is primarily the identity boundary**, while the **subscription is the Azure resource and billing boundary**.

One tenant can contain or be associated with many Azure subscriptions.

**Keywords:** subscription, billing boundary, RBAC, Policy, quotas, Entra tenant, governance

### **T01-E08. What is an Azure resource group?**

**Answer:**
An Azure resource group is a **logical container used to manage related Azure resources together**.

Resources that belong to the same application, environment, team, or lifecycle are often placed in the same resource group.

A resource group also acts as a management scope. I can apply things such as:

* Azure RBAC,
* resource locks,
* tags,
* Azure Policy assignments,
* deployments

at the resource-group level.

**Example:**
For an application, I could have:

`rg-payment-prod`

containing:

* VM or AKS-related resources,
* networking components,
* storage resources,
* monitoring resources.

If those resources have the same lifecycle, managing them together makes administration easier.

**Important point:**
A resource can belong to **only one resource group at a time**, but resources inside the same resource group can exist in **different Azure regions**.

Also, deleting a resource group generally deletes the resources contained within it, so I treat resource groups as important lifecycle boundaries.

**Memory line:**
**Subscription contains resource groups; resource groups contain resources.**

**Interview trap:**
A resource group is **not a networking boundary or a regional boundary**. Two resources can be in the same resource group but in completely different VNets or even different Azure regions.

**Keywords:** resource group, logical container, lifecycle, RBAC scope, locks, resources
