# 1. 🔴 M IMP — Azure Fundamentals, Architecture & Resource Hierarchy

## Easy

### **T01-E01. What is Microsoft Azure?**

**Answer:**
Microsoft Azure is Microsoft’s cloud computing platform. It provides on-demand services for **compute, networking, storage, databases, identity, security, monitoring, containers, and application hosting** from Microsoft-managed datacenters.

From a DevOps or cloud-engineering perspective, Azure lets me provision infrastructure programmatically, scale resources when demand changes, integrate identity and security controls, and operate workloads without managing the underlying physical datacenter. Azure supports everything from virtual machines and Kubernetes to managed databases and serverless applications. ([Microsoft Learn][1])

**Example:**
For a production application, I might use:

* Azure VNet for networking
* AKS for containers
* Azure Container Registry for images
* Azure SQL for the database
* Key Vault for secrets
* Azure Monitor for observability

All of those services are part of the Azure platform.

**Interview trap:**
Azure is not just “virtual machines in Microsoft datacenters.” It includes **IaaS, PaaS, managed services, serverless, identity, networking, security, and many other cloud capabilities**.

**Keywords:** Microsoft cloud platform, on-demand services, compute, networking, storage, managed services, scalability

---

### **T01-E02. What is cloud computing?**

**Answer:**
Cloud computing means consuming computing resources such as **servers, storage, databases, networking, and applications on demand over a network**, instead of purchasing and operating all the underlying physical infrastructure yourself.

The main idea is that resources can be provisioned quickly, scaled when required, and usually consumed through a **usage-based model**. The cloud provider operates the underlying datacenter infrastructure, while the amount of infrastructure that I manage depends on whether I use IaaS, PaaS, or SaaS. Microsoft explicitly treats deployment models and the shared-responsibility model as core cloud concepts. ([Microsoft Learn][2])

**Example:**
Instead of buying physical servers for a workload that needs 20 servers during peak traffic, I can provision Azure VMs or managed compute resources when needed and scale them down afterward.

**Interview trap:**
Cloud computing does **not** mean the customer has no operational responsibility. Responsibility is shared with the cloud provider, and the split changes depending on the service model. ([Microsoft Learn][3])

**Keywords:** on-demand resources, scalability, consumption model, shared responsibility, elasticity

### **T01-E03. What is the difference between public cloud, private cloud, and hybrid cloud?**

**Answer:**
The main difference is **who owns or consumes the infrastructure and where workloads run**.

* **Public cloud:** Cloud infrastructure is operated by a provider such as Microsoft Azure and provides services to multiple customers using logically isolated resources.
* **Private cloud:** Cloud infrastructure is dedicated to a single organization. It may run in the organization's own datacenter or be hosted by another provider.
* **Hybrid cloud:** Combines private or on-premises infrastructure with public cloud services and allows the organization to use both as part of its architecture. Microsoft treats public, private, and hybrid as the primary cloud deployment models. ([Microsoft Learn][4])

**Example:**
A company may keep a legacy database in its datacenter because of regulatory or technical requirements but run its frontend and application tier in Azure. Connectivity such as **VPN or ExpressRoute** can connect the two environments.

**Memory line:**
**Public = provider-operated shared cloud.
Private = dedicated to one organization.
Hybrid = private/on-prem + public cloud together.**

**Interview trap:**
Hybrid cloud does not simply mean “using two cloud providers.” Using Azure and AWS together is normally described as **multi-cloud**. Hybrid specifically involves combining public-cloud resources with private/on-premises environments.

**Keywords:** public cloud, private cloud, hybrid cloud, on-premises, dedicated infrastructure, multi-cloud

### **T01-E04. What is IaaS, PaaS, and SaaS?**

**Answer:**
IaaS, PaaS, and SaaS describe **how much of the technology stack the cloud provider manages for me**.

| Model    | Provider manages                              | I manage                                                      | Azure/Microsoft example                       |
| -------- | --------------------------------------------- | ------------------------------------------------------------- | --------------------------------------------- |
| **IaaS** | Physical datacenter, hardware, virtualization | OS, applications, configurations, much of networking          | Azure Virtual Machines                        |
| **PaaS** | Infrastructure, OS, runtime/platform          | Application, data, configuration                              | Azure App Service, Azure Functions, Azure SQL |
| **SaaS** | Almost the complete application stack         | Users, data, access and configuration relevant to the service | Microsoft 365                                 |

The key idea is that moving from **IaaS → PaaS → SaaS reduces the amount of infrastructure I operate**, but also generally reduces the amount of low-level control I have. Microsoft's current shared-responsibility guidance follows this model. ([Microsoft Learn][3])

**Example:**
If I deploy an application on an **Azure VM**, I have to patch and manage the operating system. If I use **Azure App Service**, Microsoft manages the underlying OS and platform, so I mainly manage my application, configuration, and data. ([Microsoft Learn][5])

**Memory line:**
**IaaS = manage the VM.
PaaS = manage the application.
SaaS = use the application.**

**Interview trap:**
PaaS does **not** mean Microsoft becomes responsible for everything. The customer still owns important responsibilities such as **data, identities, access configuration, and application-specific security**. ([Microsoft Learn][3])

**Keywords:** IaaS, PaaS, SaaS, shared responsibility, control vs management overhead, managed platform
